【什麼是 Haven】

Haven 是 KID 的自主 agent 系統，運行於 GMK Mini PC（WSL2）。
它是一個完全獨立的小型 agent 作業系統，不依賴任何外部平台。
基於 Claude Code 源碼洩漏的六項設計模式，經過 702 項測試驗證。

2026-06-08 晚間完成 Discord Bot 部署，正式獨立上線。


【v0.2 更新內容】

- 接入 DeepSeek v4 Flash API（透過 OpenRouter）
- Discord Bot 獨立上線（systemd 長期背景服務）
- 完全脫離 OpenClaw 模型層，具備獨立推理能力
- 開機自動啟動，死機 10 秒自動重啟


【六項核心設計來源】

1. 權限框架（CC: yoloClassifier.ts + denialTracking.ts）
   - 三層檢查鏈：規則 → Hook → 預設拒絕
   - 拒絕追蹤：連續 3 次或累計 20 次拒絕 → 自動降級手動模式

2. Session 管理（CC: query.ts async generator）
   - Generator 模式，五階段 pipeline
   - 七個 Continue Sites，原子狀態賦值
   - 支援暫停/恢復，JSON 序列化

3. 預算控制（CC: MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES）
   - 三層預算：Task Budget + Max Turns + Circuit Breaker
   - CC 教訓：每天浪費 25 萬次 API 呼叫，三行程式碼修復

4. Context 壓縮管道（CC: 五層簡化為三層）
   - Level 1: 截斷輸出（O(1)）→ Level 2: 選擇清理（O(n)）→ Level 3: LLM 摘要
   - 斷路器保護：連續 3 次失敗停止壓縮

5. ToolSearch 延遲工具載入（CC: defer_loading）
   - 核心工具預設可見，延遲工具按需搜尋
   - 已成業界標準（OpenAI SDK、ZeroClaw、CrewAI）

6. 模組化架構（CC: 4600+ 檔案啟發）
   - 零循環依賴，DAG 結構
   - 每個子系統可獨立抽換，最多改 1 個檔案

【KAIROS 記憶系統】

三層閘門（便宜先檢查）：
1. 時間閘 — 距上次記憶鞏固 ≥ 24 小時
2. Session 閘 — 累積 ≥ 5 個新 session
3. Lock 閘 — 取得檔案 advisory lock

Lock 設計（對應 CC consolidationLock.ts）：
- mtime = lastConsolidatedAt
- body = 持有者 PID
- 1 小時過期（PID 重用防護）
- mtime 不回寫 = 天然 rollback


【系統化身】

CC BUDDY pet 重新構想 —— 系統健康指標。

五項數值對應真實系統狀態：
除錯（debugging）· 耐心（patience）· 混亂（chaos）
智慧（wisdom）· 警戒（snark）

七種姿態：zZ 睡眠 / ^_^ 安穩 / ^o^ 活躍 /
          >_< 緊張 / @_@ 警戒 / .o. 孵化 / ~u~ 做夢

夜間自動睡眠（23:00-08:00），除非警戒。

【Provider Chain 最終結構】

  ┌─ Primary:  DeepSeek v4 Flash (via DeepSeek API)
  ├─ Fallback: Gemma 4 26B (via OpenRouter)
  └─ Tertiary: Seed 2.0 Lite (via Ark)

  Circuit breaker per provider：
    3 次連續失敗 → OPEN（跳過），30s 後 → HALF_OPEN（試一次）
    成功 → CLOSED，失敗 → OPEN


【Transport 層最終結構】

  ┌─ TransportAdapter（抽象基底）
  │   ├─ _send_text(channel_id, text)
  │   ├─ _send_file(channel_id, path, name)
  │   ├─ _extract_user_id(msg)
  │   ├─ _extract_text(msg)
  │   └─ _extract_channel_id(msg)
  │
  ├─ DiscordAdapter → DiscordBot（via discord.py）
  │
  └─ TelegramAdapter → run_telegram（via python-telegram-bot）

  共享 pipeline：whitelist → mention strip → router.process → file delivery


【Config 結構化 — 環境變數變動】

  新增 typed fields（core/config.py）：
    primary_model, fallback_model, tertiary_model, embed_model

    ollama_base_url, heartbeat_url

    heartbeat_discord_channel, heartbeat_discord_user

    HAVEN_TELEGRAM_TOKEN（fallback: TELEGRAM_TOKEN）

【記憶淘汰機制】

  LongTermMemory.evict() 雙策略：
    1. TTL：30 日未存取 → 刪除（config.memory_eviction_ttl_days）
    2. LRU：超過 1000 條 → keep 最新（config.memory_max_entries）
    自動觸發：add() 後自動 evict


【FakeProvider 測試基建】

  FakeProvider 特性：
    - 可預設 response 序列（ProviderResponse list）
    - 每 call 順序彈出下一個 response
    - call_count 記錄調用次數
    - 支援 tool_calls（模擬 LLM 工具選擇）
    - 可嵌入 circuit breaker + tracer 場景

  FailingProvider：每次呼叫拋出例外，測試 fallback chain
