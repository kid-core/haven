  python3 dev/kid/main.py


【操作指引】

  手動啟動——

    方法一（systemd，推薦）：
      systemctl --user start haven.service

    方法二（前景執行，可看到終端提示符）：
      cd /mnt/z/Haven
      .venv/bin/python dev/kid/main.py
      啟動後會顯示 banner 和「Cris>」終端提示符
      輸入 exit 離開終端模式（Discord/Telegram 仍會保持運行）

    方法三（純背景執行，無終端）：
      cd /mnt/z/Haven
      HAVEN_NO_TERMINAL=1 .venv/bin/python dev/kid/main.py &
      只啟動 Discord + Telegram，不載入終端互動模式

  手動重啟——

    方法一（systemd，推薦）：
      systemctl --user restart haven.service
      服務會自動先停止再啟動，無需手動 kill

    方法二（手動重啟）：
      1. 找出 Haven 進程：
           ps aux | grep main.py | grep -v grep
      2. 安全停止舊進程（見下方）
      3. 用上方啟動指令重新啟動

  安全停止——

    方法一（systemd，推薦）：
      systemctl --user stop haven.service
      發送 SIGTERM，Haven 會 graceful shutdown：
        - Discord / Telegram connection 正常關閉
        - 當前任務完成後才退出
        - Crash journal 寫入最後狀態

    方法二（終端模式下）：
      在「Cris>」提示符輸入 exit
      系統會顯示「Haven shut down gracefully」

    方法三（背景運行時）：
      發送 SIGTERM（非 SIGKILL）：
        kill <PID>
      Haven 會觸發 graceful shutdown 流程

    ⚠️ 注意：
      切勿使用 kill -9（SIGKILL），會跳過 graceful shutdown，
      可能導致 sessions.json 未保存。

  檢查狀態——

    systemctl --user status haven.service
    或
    ps aux | grep main.py | grep -v grep
    （看到 /mnt/z/Haven/.venv/bin/python main.py 即為運行中）


【支援的指令】

  /goal —— 管理持久化目標
    /goal add <title>                           建立新目標
    /goal add <title> | <description>           建立目標（含描述）
    /goal list                                  列出所有目標
    /goal status                                顯示狀態摘要
    /goal progress <id> <0-100>                 更新進度
    /goal done <id>                             標記完成
    /goal cancel <id>                           取消目標
    /goal help                                  顯示說明

  /cron —— 管理排程（P7）
    /cron add "0 9 * * *" "title"               建立每日排程
    /cron add "*/30 * * * *" "title"            建立定時排程
    /cron list                                  列出所有排程
    /cron remove <id>                           移除排程
    /cron help                                  顯示說明

  （更多 slash command 規劃中）


【Haven 的自動回應規則】

  Haven 在以下情況會回應：
    1. 被 @mention（任何頻道）
    2. 私訊（DM）
    3. 在 HAVEN_LISTEN_CHANNELS 指定的頻道（免 @mention）
    4. 在 HAVEN_LISTEN_GUILDS 指定的伺服器所有頻道（免 @mention）

  設定範例（.env）：
    HAVEN_LISTEN_CHANNELS=1514517002730078228
    HAVEN_LISTEN_GUILDS=1514508652420268093


【Haven 會自動做的事】

  情境感知：
    - 讀取長期記憶（116 項，Vector Index）
    - 載入 Skill 摘要（P5a 兩階段模式）
    - 注入當前 active goals 到 system prompt

  排程執行：
    - 支援 cron expression 排程
    - 支援一次性（AT）和重複（EVERY）排程
    - 排程持久化，重啟後自動恢復

  成本控制：
    - 每 turn 自動追蹤 token 用量
    - 超出預算時自動切換 fallback provider
    - primary（DeepSeek V4 Pro）→ fallback（Gemma 4 26B）

  自我診斷：
    - Heartbeat 每 30 秒檢查 provider 健康
    - Circuit Breaker 隔離故障 provider
    - Crash Journal 記錄崩潰，自動恢復

【例外處理架構】

  fallback chain（三層）：
    Primary (DeepSeek V4 Pro) → Fallback (Gemma 4 26B) → Tertiary (Ark seed-2-0-lite)
    每層有獨立 Circuit Breaker（5 次失敗觸發 60 秒熔斷）

  Heartbeat：
    每 30 秒檢查 provider 健康
    連續 3 次失敗 → 標記 unhealthy

  Crash Journal：
    崩潰時記錄 traceback + 狀態
    下次啟動自動檢查並恢復
