## 🔥 死機事件 — 完整戰後檢討

### 時間線
- **17:53** — 我將 `tailscale` 設定寫入 config（放錯位置）
- **18:32** — Gateway 重啟後 crash，錯誤：`tailscale funnel requires gateway auth mode=password`
- **18:32~31** — systemd 重試 5 次全失敗，放棄
- **18:35** — Cris 嘗試重啟失敗（config 已損毀）
- **18:41** — 移除 `gateway.tailscale` 後成功啟動 ✅

### 死因
我將 `tailscale` 設定放在 `gateway` 層級（`gateway.tailscale.mode: "funnel"`），但 OpenClaw 規定：
→ `gateway.tailscale.mode = "funnel"` 強制要求 `gateway.auth.mode = "password"`
→ 我們用 `token` auth，所以直接不給啟動

正確位置是 `hooks.gmail.tailscale`，不是 `gateway.tailscale`

### 五大教訓
1. **Config 區塊有嚴格 schema** — 不能亂塞
2. **`gateway.tailscale` ≠ `hooks.gmail.tailscale`** — 位置錯了會出事
3. **改 config 前要先 validate** — `openclaw config validate`
4. **死機自救法** — systemd 重試 5 次後放棄，要手動 `reset-failed` 才能再次啟動
5. **Clobbered backup 是救命符** — OpenClaw 會自動備份壞 config，可以 rollback

### 目前 config
- `gateway` 層級：乾淨，無 `tailscale` 區塊
- `hooks.gmail.tailscale`：`mode: "funnel", path: "/gmail-pubsub"` ✅
